# Optional AI provider evaluation

The desktop app has bounded, opt-in code editing for a selected Harlowe or SugarCube passage: repair existing story-format code, propose one conditional choice to an existing passage, add one choice and new empty destination passage, or propose a two-way fork with two empty destinations. It is an experimental coding aid, not a prose-writing or autonomous story-editing service. The browser app shows that the action is desktop-only. No provider key is bundled, and the app makes no inference request without a user-provided key and a native confirmation for that request.

## OpenCode Go boundary

OpenCode currently describes Go as access for OpenCode and similar coding agents. The adapter checks the public `GET https://opencode.ai/inference/go/v1/models` list before each request. It prefers `deepseek-v4.1-flash` and, when absent, selects `glm-5.3-flash` or `mimo-v2.6-flash` in that order only if the provider lists them. These are documented Go coding models. The selected model is shown in the native confirmation before the app uses the OpenAI-compatible Chat Completions endpoint. It sends a product-specific User-Agent and a stable `x-opencode-session` per request. Model availability and policies can change.

- Go documentation and current model privacy: https://dev.opencode.ai/v2/docs/console/go/
- Inference API: https://dev.opencode.ai/v2/docs/console/api/inference/
- Terms: https://opencode.ai/legal/terms-of-service

Use **Manage OpenCode Go key** in the desktop AI panel to enter your own key. The separate credential window contains no story content and exposes only status, save, and clear operations to the Electron main process. The key is encrypted with Electron's OS-backed `safeStorage` and saved in a dedicated file under app user data; the app refuses to save it when secure storage is unavailable or Linux selects `basic_text`. `TWINE_STUDIO_OPENCODE_GO_KEY` remains an optional environment override for development and takes precedence over a saved key. An environment key must be removed outside the app. The key is never returned through the story renderer bridge or saved in story, browser, or app-preference storage. Model discovery is unauthenticated. Each inference request is user initiated, limited to one active request, capped in size and time, and cancelable by its session. The app does not retry paid requests automatically.

The request contains the selected passage source, passage name and ID, story format and version, a fixed coding task, and a session ID. Conditional-choice requests also contain the author's instruction and up to 100 existing destination names and IDs, but no destination passage bodies. One- and two-way branch requests contain the author's instruction but no other passage bodies. The UI presents the disclosure and current model privacy link before a consent checkbox; the native prompt defaults to Cancel. Authors should check the current privacy policy before sending source. Provider terms limit Go to coding-agent-like traffic and internal use; these actions deliberately exclude general fiction generation.

For repair, the model can return only a proposed single-passage text update. Strict parsing rejects unsupported fields, a changed passage ID, unchanged text, oversized output, and changes to passage links. For conditional choices, the model returns only a fact name, comparison, value, plain-text label, and existing destination ID. Twine Studio validates those parameters and generates the format-specific source locally. An accepted conditional choice appends one link; it cannot create or rename a passage. For a new branch, the model proposes only a plain-text choice label and new passage name. A two-way fork proposes exactly two distinct label/name pairs. Studio validates uniqueness and name safety, generates the links, and creates empty destination passages. The editor lets the author select either or both routes; the after-source preview updates to show exactly those links, and accepting none is disabled. Accept applies the selected routes as one undoable change only when the selected source and format still match, the conditional destination is unchanged, or the proposed branch names remain free. Reject or close leaves the story unchanged. Model output remains untrusted data, so authors should inspect syntax and story behavior after accepting it.

## Evidence and remaining limits

Mocked tests cover endpoint selection, headers, no-key behavior, native denial, one active request, session-scoped cancellation, invalid proposals, conditional and branch source generation, existing destinations, name collisions, stale-source refusal, and one-step branch undo/redo. The two-way fork additionally checks both destinations, selective source preview, map placement and one-step undo of an accepted route. The web browser journey confirms opening the desktop-only panel preserves passage text through reload. A real paid inference round trip has **not** been run because no user key was supplied; model quality, cost, provider failures and native end-to-end review/undo still need live acceptance. The environment-variable setup is intentionally minimal credential handling, not a complete credential-management UI. This feature does not close the broader AI-modification journey or release acceptance.
